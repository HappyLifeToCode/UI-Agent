# 清洗规则文档

> 版本 v0.1 | 维护:谭 | 最后更新:2026-07-25
> 本文档是数据清洗与脱敏的规则权威。规则变更:先改本文档,再改代码,24h 内同步。

## 1. 脱敏规则

原则:**原始轨迹(wire.jsonl)原样保留,脱敏只在转换管线出口统一执行**,
不回写原始数据(契约 §1)。

| #   | 类型             | 匹配模式(正则)                                | 替换为              | 实施位置                              | 状态    |
|-----|----------------|-----------------------------------------|------------------|-----------------------------------|-------|
| 1   | Windows 用户路径   | `[A-Za-z]:[\\/]+Users[\\/]+[^\\/\s"']+` | `<HOME>`         | `wire2messages.py sanitize()`     | ✅ 已实施 |
| 2   | Linux/Mac 用户路径 | `/(Users                                | home)/[^/\s"']+` | `<HOME>`                          | 同上    | ✅ 已实施 |
| 3   | API key        | `sk-[A-Za-z0-9]{20,}`                   | 检出即拒收            | `qa/validator.py check_secrets()` | ✅ 已实施 |
| 4   | Bearer token   | `Bearer\s+[A-Za-z0-9._-]{20,}`          | 检出即拒收            | 同上                                | ✅ 已实施 |
| 5   | Cookie 值       | `Set-Cookie: ...`                       | `<COOKIE>`       | 预案(未在数据中出现)                       | ⏳ 待实施 |
| 6   | 代理凭证           | `user:pass@host`                        | `<PROXY_CRED>`   | 预案(使用住宅代理时启用)                     | ⏳ 待实施 |

规则 3、4 的处理方式与其他不同:密钥**不允许出现在样本中**,检出即整条拒收
并记录 issue,不做替换保留(防止替换不彻底)。

## 2. 编码与 GBK 乱码

- 所有文件读取统一 **UTF-8**;wire.jsonl 原样保存,不改编码;
- 当前批次数据未出现 GBK 乱码(实测 task_0001~0003);
- **预案**:若某条样本出现乱码(如 Playwright 在中文 Windows 的 GBK 输出),
  处理流程:① 在 issue 中记录位置;② 尝试 GBK 解码修复(`bytes.decode("gbk",
  errors="replace")`);③ 无法修复的字段替换为 `<GARBLED>` 并在 meta 标注;
  ④ 该样本标记人工复核。

## 3. 人工复核规则(自动判据 + 抽检)

以下情况**必须人工复核**,不得仅凭自动判据入库:

| 情况           | 判据                                           | 复核内容                 |
|--------------|----------------------------------------------|----------------------|
| captcha 但有截图 | `status=="captcha"` 且 `has_screenshot==true` | 截图是作者主页还是验证码页        |
| 整页截图         | 每个任务                                         | 截图非空白、非验证页、内容为目标人物主页 |
| 乱码修复样本       | meta 有修复标注                                   | 修复后内容是否可读、合理         |
| 抽检           | 每批随机 ≥10%                                    | 对照 wire 与样本,检查转换保真度  |

## 4. 规则维护流程

1. 发现新的泄露/乱码模式 → 当日记录;
2. 24h 内:更新本文档 → 更新 `sanitize()` / `validator.py` → 重跑管线;
3. 群里 @ 全员同步(对应"格式偏差 24h 同步"条款);
4. 已入库数据受影响的:标注受影响样本范围,重新转换生成新版本。
